# Windows venue installation and updates with Git

The venue computer runs the player and the display built from this repository. Videos stay in the local `venue-media` folder. Participation and show timing still use the live venue server. The tracked lobby QR is included in the local display build.

## First installation (technician)

Install Git for Windows, Node.js 22+ and Microsoft Edge. Open PowerShell and run:

```powershell
npm.cmd install --global pnpm@9.12.2
cd C:\
git clone --branch venue-mode https://github.com/ale-rls/smartphonecracy-runner.git
cd smartphonecracy-runner
Copy-Item scripts/venue.env.example .env.venue
notepad .env.venue
```

Set `DISPLAY_TOKEN` to the existing live venue server's display token. Confirm the server and realtime WebSocket URLs. The token is obtained from the installation administrator/server configuration; do not use the development token. `.env.venue` is ignored by Git. Do not copy the development machine's general `.env` file.

Copy the supplied videos from USB into `C:\smartphonecracy-runner\venue-media`. If using the previous USB archive, copy only its `venue-media` folder; the standalone `player.mjs` and its launchers are not used for this installation.

Build and test:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/setup-venue.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start-venue.ps1 -OpenBrowser
```

The launcher starts the local gateway and opens Edge fullscreen with sound enabled when the live show server is ready. The first page load verifies the local videos against the live manifest. Test the lobby QR, a phone join, sound and video on this Windows host.

`pnpm venue:build` reads the current live build version automatically, preventing a local display/server version mismatch. It uses the token and URLs from `.env.venue`. No videos are downloaded or regenerated by the build.

## Browser settings at startup

### Foreground window

Both Windows launchers explicitly open Edge in a normal window state, then use `focus-edge.ps1` to find the dedicated venue profile's window, restore it if minimized, and retry foreground activation for up to 30 seconds. The helper confirms focus for three consecutive checks and logs a warning if activation never succeeds. It releases temporary topmost status immediately, so staff can still switch apps afterwards. The portable package must include `focus-edge.ps1` beside `start-windows.ps1`.

Test a Windows reboot after updating. Windows can restrict [foreground activation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow); the startup log confirms whether it succeeded on this host.

### Translation prompts

When `-OpenBrowser` is used, the launcher sets the supported Edge `TranslateEnabled` policy to `0` in `HKCU:\Software\Policies\Microsoft\Edge` before opening Edge. This disables built-in translation and its prompts for the current Windows user, including that user's other Edge profiles. Use the dedicated venue Windows account. Other Windows accounts are unaffected.

Close the venue Edge window before restarting the launcher after this update. On managed computers, IT should ensure the effective `TranslateEnabled` value in `edge://policy` is false; an organization policy can take precedence. See [Microsoft's TranslateEnabled documentation](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/translateenabled).

To undo after retiring this launcher, run `Remove-ItemProperty -Path 'HKCU:\Software\Policies\Microsoft\Edge' -Name TranslateEnabled` and restart Edge. Running the launcher with `-OpenBrowser` applies the policy again.

### Autoplay

The launcher passes `--autoplay-policy=no-user-gesture-required` to Edge and opens the display with `?sound=1`. The URL parameter unmutes the app; the Edge flag permits playback without a click. Microsoft documents this flag for [audible playback in kiosk mode](https://github.com/MicrosoftDocs/SupportArticles-docs/blob/main/support/microsoft-edge/development/video-playback-issues.md#kiosk-mode).

For a managed venue PC, ask IT to allow `http://localhost:3000` through Edge's [AutoplayAllowlist policy](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/autoplayallowlist), then check the effective settings at `edge://policy`. This site-specific permission is not installed by these scripts. The launcher uses a separate Edge profile so it does not reuse an ordinary browsing session.

Before handover, restart Windows and verify lobby audio, show audio, and sound effects without clicking the page. Also check the Windows output device and volume. Autoplay is not guaranteed until tested with the host's actual browser and managed policies. Currently, `?sound=1` hides the app's Enable sound button even if playback is blocked; as a manual recovery, open `/display/` without that parameter and use Enable sound. This is a recovery step, not the normal staff startup procedure.

## Automatic opening for venue staff

After the test, close Edge with Alt+F4 and stop the launcher with Ctrl+C. Install automatic startup while signed into the Windows account used at the venue:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install-venue-startup.ps1
Start-ScheduledTask -TaskName "Smartphonocracy Venue Player"
```

Afterwards, the player and fullscreen Edge start at Windows sign-in. Staff do not need to open Edge, enter a URL, use F11, or run Git. Automatic Windows sign-in is a separate venue IT setting. The launcher restarts the player after a failure; it does not reopen Edge if a person closes the browser.

If the earlier standalone package's `ENABLE-AUTOSTART.cmd` was used, first remove its `Smartphonocracy Venue` shortcut from `shell:startup` (Win+R). Run only one launcher.

## Later updates (technician, outside show hours)

First deploy any intended coordinator changes to the live venue server and wait until it is ready. Then update the venue PC so its display is built against that live version:

1. Close Edge with Alt+F4.
2. Stop the scheduled task (or use Ctrl+C if the launcher was started manually):

   ```powershell
   Stop-ScheduledTask -TaskName "Smartphonocracy Venue Player"
   ```

3. From the repository folder:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/setup-venue.ps1 -Update
   ```

   This runs `git pull --ff-only`, installs locked dependencies, and rebuilds the display. It refuses to update tracked files with local edits. It preserves `.env.venue` and `venue-media`. If any step fails, resolve the reported problem before restarting.

4. Start the player again:

   ```powershell
   Start-ScheduledTask -TaskName "Smartphonocracy Venue Player"
   ```

5. Verify the lobby QR, audio and phone join. If a release changes videos, copy the matching media delivery too; Git does not contain those files.

Do not schedule unattended `git pull` during venue operation. Logs are in `%LOCALAPPDATA%\Smartphonocracy`. To remove automatic startup, use `Unregister-ScheduledTask -TaskName "Smartphonocracy Venue Player"`.

The Windows launch scripts must be acceptance-tested on the actual Windows host; builds and server tests can also run on macOS/Linux.
